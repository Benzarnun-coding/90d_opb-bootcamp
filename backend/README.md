# Backend — แผนงานแบ่งเป็นเฟส

รุ่นจริงมีนักเรียน **200–250 คน** ตัวเลขนี้เปลี่ยนโจทย์ไปพอสมควร
เอกสารนี้แยกงานเป็นเฟส เรียงจากง่ายไปยาก พร้อมบอกว่าเฟสไหน **ต้องเสร็จก่อนเปิดรุ่น**

```
backend/
  migrations/001_core.sql          ตาราง + RLS + trigger          [Phase 1 · เสร็จ]
  migrations/002_scale.sql         view สรุปผล + index           [Phase 2 · SQL เสร็จ]
  migrations/003_houses.sql        4 ห้อง + รายชื่ออีเมล          [Phase 3a · SQL เสร็จ]
  migrations/004_weekly_pledge.sql คำสัญญารายสัปดาห์             [Phase 3c · SQL เสร็จ]
  migrations/005_no_review.sql     ถอดระบบตรวจงานออก            [Phase 3d · SQL เสร็จ]
  migrations/006_notify.sql        คิวแจ้งเตือน + view คนที่ต้องตาม  [Phase 4 · SQL เสร็จ]
  functions/notify/index.ts        Edge Function ส่งเข้า LINE       [Phase 4 · รอ deploy]
  seed/dev_seed_250.sql            ข้อมูลทดสอบ 250 คน
  test/smoke.sql                   ตรวจว่ากันโกงได้จริง
```

รันตามลำดับใน Supabase SQL Editor: `001` → `002` → `003` → `004` → `005` → (ถ้าเป็นโปรเจกต์ทดสอบ) `seed` → `test`

---

## สิ่งที่ 250 คนทำให้พัง

**1. เบราว์เซอร์นักเรียนจะค้าง**
ถ้าดึง submissions ทั้งหมดมาคำนวณในเครื่อง 250 คน x 84 วัน จะเป็นหมื่นแถว
มือถือนักเรียนไม่ไหว → **แก้ใน Phase 2** ด้วยการให้ Postgres สรุปมาให้แล้ว

**2. ภาระตรวจงาน — แก้แล้วด้วยการเลิกตรวจ**
เดิมคือ 250-400 ชิ้นต่อวัน ซึ่งไม่มีทางไหว ตอนนี้ส่งแล้วนับทันที (Phase 3d)
ปัญหานี้หายไปทั้งหมด

**3. ลิมิตของ Supabase แพ็กเกจฟรี**
- อีเมลล็อกอินส่งได้ไม่กี่ฉบับต่อชั่วโมง → 250 คนสมัครวันเดียวกันไม่รอด **ต้องใช้ Google login**
- realtime รับได้ 200 การเชื่อมต่อพร้อมกัน → ถ้าเปิดพร้อมกันเกิน 200 จะมีคนหลุด
  ทางเลือกคืออัปเป็น Pro (~$25/เดือน) หรือดึงข้อมูลใหม่ทุก 30 วินาทีแทน
- ขนาดฐานข้อมูลไม่ถึง 30MB จากลิมิต 500MB ไม่ต้องห่วง

**4. สนามแข่ง 250 เลน**
ค่าเริ่มต้นแสดงเฉพาะคนใกล้ตัว 7 เลน มีปุ่มดูทั้งรุ่นและกรองรายห้อง
ส่วนหน้า Scoreboard แสดงครบทุกคนในตารางซึ่งรับ 250 แถวได้สบาย

## Phase 1 — แกนกลาง ✅ เสร็จแล้ว

`migrations/001_core.sql`

ตาราง `cohort` `profiles` `enrollments` `submissions` พร้อม Row Level Security และ trigger
ที่บังคับกติกาสำคัญไว้ที่ฐานข้อมูล ไม่ใช่ที่หน้าเว็บ — งานที่ส่งมาถูกบังคับเป็น "รอตรวจ" เสมอ
วันที่คิดจากเวลาเซิร์ฟเวอร์ ลิงก์ซ้ำถูกบล็อก และมีเฉพาะโค้ชที่แก้สถานะงานได้

หน้าเว็บที่มีอยู่ตอนนี้ต่อกับเฟสนี้ได้เลย ใส่คีย์ใน `config.js` แล้วใช้งานได้

## Phase 2 — รองรับ 250 คน ✅ เสร็จแล้วทั้งสองฝั่ง

`migrations/002_scale.sql`

ย้ายการคำนวณทั้งหมดไปไว้ที่ Postgres แล้วให้เบราว์เซอร์ดึงแค่ผลสรุป

| view | ใช้ทำอะไร | ขนาดที่ดึง |
|---|---|---|
| `v_leaderboard` | กระดานหลัก 1 แถวต่อ 1 คน มีครบทั้งระยะทาง เป้า streak วันลา ดาวเฉลี่ย | 250 แถว |
| `v_sprint_stats` | สรุปรายสปรินต์ ใช้วาดแถบ 6 ช่องในตาราง | 1,500 แถว |
| `v_feed` | ฟีดงานล่าสุด | 50 แถว |
| `v_review_queue` | คิวตรวจของโค้ช เรียงธงแดงขึ้นก่อน | เฉพาะที่ค้าง |

**ฝั่งเว็บต่อเรียบร้อยแล้ว** `LiveDB.fetchAll()` ดึงจาก `v_leaderboard` + `v_feed`
รวม 250 แถว + ฟีด 50 แถว + คำสัญญาของตัวเองอีกไม่กี่แถว แทนการลากงานทั้งรุ่นสองหมื่นแถว
สถิติทุกตัวอ่านจากที่ Postgres คิดมาแล้ว ส่วนแผนที่รายวันของแต่ละคนโหลดเฉพาะตอนเปิดโปรไฟล์
ผ่าน `DB.detail()` ไม่ได้ดึงมาทั้งรุ่น

**วิธีตรวจว่าผ่าน** รัน `seed/dev_seed_250.sql` แล้วดู `explain analyze select * from v_leaderboard`
ควรต่ำกว่า 300ms ถ้าช้ากว่านั้นเปลี่ยนเป็น materialized view แล้วรีเฟรชทุกนาทีด้วย pg_cron

## Phase 3a — 4 ห้อง + รายชื่อที่โค้ชอัปโหลดเอง 🔶 SQL เสร็จ / ฝั่งเว็บยังไม่ทำ

`migrations/003_houses.sql`

แบ่ง 250 คนเป็น 4 ห้องตามหลักคุณธรรมสี่ของสโตอิก

| # | ห้อง | ไทย | สี | คำขวัญ |
|---|---|---|---|---|
| 1 | 🦉 WISDOM | ปัญญา | ฟ้า | รู้ว่าจะเล่าอะไร |
| 2 | ⚖️ JUSTICE | ยุติธรรม | ทอง | เล่าอย่างตรงไปตรงมา |
| 3 | 🦁 COURAGE | ความกล้า | แดง | กล้ากดปล่อย |
| 4 | 🛡️ DISCIPLINE | วินัย | เขียว | ปล่อยทุกวันไม่มีข้อแม้ |

**คะแนนยังเป็นของรายคนเหมือนเดิมทุกอย่าง** ห้องเป็นชั้นที่ครอบอยู่ข้างบนเท่านั้น
ตัวละครวิ่งด้วยคะแนนของตัวเอง เป้าเป็นของตัวเอง streak เป็นของตัวเอง
ห้องมีไว้เพื่อสามอย่าง — แบ่งงานให้โค้ช, ให้คนมีพวกไว้เชียร์กัน, และมีกระดานห้องไว้ดูภาพรวม

**การเข้าระบบเปลี่ยนไปทั้งหมด** เดิมใครมีอีเมลก็สมัครได้ ตอนนี้คุณอัปโหลดรายชื่ออีเมลของแต่ละห้อง
ไว้ล่วงหน้าในตาราง `roster` นักเรียนล็อกอินเองด้วยอีเมลนั้น ระบบจับเข้าห้องให้อัตโนมัติ
**ถ้าอีเมลไม่อยู่ในรายชื่อ จะสมัครไม่ได้เลย** — รายชื่อนี้เลยทำหน้าที่เป็นประตูของทั้งระบบไปในตัว
ใครไม่ได้จ่ายค่าคอร์สก็เข้าไม่ได้ ไม่ต้องทำระบบเช็คสิทธิ์แยกอีกชั้น
และหนึ่งอีเมลสมัครได้ครั้งเดียว บัญชีสำรองมาสวมสิทธิ์ไม่ได้

**โค้ชแบ่งเป็นสองระดับ** โค้ชประจำห้องเห็นและตรวจได้เฉพาะงานของห้องตัวเอง (บังคับที่ RLS
ไม่ใช่แค่ซ่อนในหน้าเว็บ) ส่วนหัวหน้าโค้ชเห็นทุกห้องและเป็นคนเดียวที่จัดการรายชื่อกับย้ายห้องได้

**ตัวเลขที่ดีขึ้น** 250 คนหาร 4 ห้อง เหลือห้องละ ~62 คน = ตรวจ ~62 งานต่อวันต่อห้อง
ประมาณ 21 นาทีต่อวันต่อโค้ชหนึ่งคน จากเดิมที่คุณคนเดียวต้องรับ 83 นาที
ยังไม่เบาแต่กระจายให้ผู้ช่วยได้แล้ว

**กระดานห้อง** `v_house_board` คิดจากค่าเฉลี่ยต่อคน ไม่ใช่ผลรวม เพราะถ้าห้องมีคนไม่เท่ากัน
แล้วใช้ผลรวม ห้องที่คนเยอะกว่าจะชนะอัตโนมัติตั้งแต่วันแรก มีคอลัมน์ `falling_behind`
บอกจำนวนคนที่ตามหลังเป้าเกิน 3 วัน ไว้ให้โค้ชรู้ว่าต้องไปตามใคร

**งานที่เหลือฝั่งเว็บ** หน้าอัปโหลดรายชื่อสำหรับหัวหน้าโค้ช (ตอนนี้ทำผ่าน SQL Editor ไปก่อนได้)
แถบสลับดูรายห้องในสนามแข่ง กระดานห้อง 4 ใบบนสุด และคิวตรวจที่กรองตามห้องของโค้ชที่ล็อกอินอยู่

## Phase 3c — คำสัญญารายสัปดาห์ 🔶 SQL เสร็จ / ฝั่งเว็บเสร็จแล้ว

`migrations/004_weekly_pledge.sql`

ทุกต้นสัปดาห์นักเรียนเลือกเองว่าสัปดาห์นี้จะปล่อยกี่ชิ้น

| ชิ้น/สัปดาห์ | ชื่อ | ตัวละคร | เปิดเมื่อ |
|---|---|---|---|
| 4 | COMPROMISE | ปกติ | สัปดาห์ 1 |
| 7 | RECOMMENDED | ปกติ | สัปดาห์ 1 |
| 10 | LASER FOCUS | **แดง** เฉพาะสัปดาห์นั้น | สัปดาห์ 1 |
| 14 | LASER FOCUS PRO MAX | **ติดไฟ ผมทอง** | สัปดาห์ 7 |

**แกนคะแนนคือจำนวนชิ้น ไม่ใช่จำนวนวัน** เป้าของแต่ละคนคือผลรวมคำสัญญาของตัวเอง
ถึงสัปดาห์นี้ เส้นชัยตั้งที่ 84 ชิ้น (7 x 12 = เส้นทาง RECOMMENDED)
คนเลือก 4 ทุกสัปดาห์จะไม่ถึงเส้นชัย ซึ่งถูกแล้วเพราะเขาเลือกเอง
คนเลือก 10-14 จะถึงก่อนกำหนดและวิ่งเลยเส้นไปได้

**กติกาที่ทำให้คำสัญญามีความหมาย** เลือกย้อนหลังไม่ได้ และสัปดาห์ที่กำลังวิ่งอยู่
**เพิ่มเป้าได้ แต่ลดไม่ได้** ถ้าลดได้ คนจะสัญญา 10 ไว้ก่อนแล้วพอวันศุกร์ทำไม่ไหว
ก็ลดเหลือ 4 แล้วยังนับว่าทำครบ กลไกทั้งอันจะไร้ความหมาย

**streak เป็นรายสัปดาห์** = กี่สัปดาห์ติดกันที่ทำได้ตามที่สัญญา
สัปดาห์ที่ไม่ได้ลงสปรินต์ ข้ามไปเฉย ๆ ไม่ตัด streak

## Phase 3d — ถอดระบบตรวจงานออก ✅ เสร็จแล้ว

`migrations/005_no_review.sql`

ส่งลิงก์แล้ว **นับทันที** ไม่ต้องรอใครตรวจ ไม่มีดาว ไม่มีคะแนน CRAFT
วันหนึ่งส่งกี่ชิ้นก็ได้ ส่งเกินเป้าก็ได้ ไม่มีเพดานต่อวันแล้ว

การตัดสินใจนี้ทำให้ปัญหาที่หนักที่สุดของโปรเจกต์หายไปทั้งหมด — ภาระตรวจงาน
250-400 ชิ้นต่อวันที่เคยเป็นเหตุผลว่าทำไมต้องมี Phase 3b ไม่มีอีกแล้ว
และตัวละครขยับทันทีที่กดส่ง ซึ่งเป็นจังหวะที่เกมควรให้รางวัลอยู่แล้ว

สิ่งที่ยังเหลือไว้คือ **กันลิงก์ซ้ำ** (ทั้งรุ่น ไม่ว่าใครส่ง) กับ **ธงแดง**
เมื่อลิงก์ไม่มี handle ของเจ้าตัว แต่ธงเป็นแค่ข้อมูลให้ดู ไม่บล็อกอะไร
หัวหน้าโค้ชยังลบงานที่มั่วออกได้ด้วยการตั้ง `status = rejected`

ถ้าวันหนึ่งอยากได้ระบบให้ดาวกลับมา แค่แก้ `on_submission_insert`
ให้ตั้ง `status = pending` เหมือนเดิม โครงเดิมยังอยู่ครบ

**Phase 3b (วาล์วนิรภัย + เครื่องมือตรวจงาน) จึงยกเลิกไป** ไม่ต้องทำแล้ว

## Phase 4 — แจ้งเตือน 🔶 โค้ดพร้อมแล้ว รอ deploy

ตอนนี้ระบบไม่เตือนใครเลย และนักเรียนต้องจำเองว่าโพสต์เสร็จแล้วต้องมาวางลิงก์
ซึ่งเป็นจุดที่คนจะหายไปมากที่สุดตั้งแต่สัปดาห์ที่ 3

- ตาราง `notifications` เป็นคิว + Supabase Edge Function ยิงตามเวลา
- เตือนสามทุ่มเฉพาะคนที่ยังไม่ส่งงานวันนั้น
- เตือนตอนโค้ชตีกลับงาน และตอนใกล้หลุด streak
- ถ้าต่อ **LINE Messaging API** ได้จะดีที่สุด เพราะแก้ปัญหา "ลืมมาวางลิงก์" ไปพร้อมกัน —
  วางลิงก์ในแชทกลุ่มแล้วบอทบันทึกให้เลย ไม่ต้องเปิดเว็บ

## ลำดับที่แนะนำให้ลงมือ

1. สร้างโปรเจกต์ Supabase **สองอัน** — `bootcamp-dev` ไว้ทดลอง กับ `bootcamp-prod` ไว้ใช้จริง
   อย่าทดลองบนตัวจริง เพราะ seed มีคำสั่งลบข้อมูลทิ้ง
2. บน dev รัน `001` → `002` → `003` → `004` → `005` → `seed` → `test`
   ดูว่าทุกข้อขึ้น PASS และ `explain analyze select * from v_leaderboard` ต่ำกว่า 300ms
3. แก้ฝั่งเว็บให้ตรงกับฐานข้อมูลใหม่ — งานก้อนเดียวกันทั้งหมด ทำทีเดียวจบดีกว่าทยอย
   เพราะแกนคะแนนเปลี่ยนจาก "วัน" เป็น "ชิ้น" แล้ว: ดึงจาก view แทนดึงทั้งตาราง,
   หน้าเลือกคำสัญญารายสัปดาห์, ตัวละครแดง/ไฟ, แถบห้อง, คิวตรวจแยกห้อง
4. ทำ Phase 3b (วาล์วนิรภัย) ให้เสร็จ ห้ามข้าม — ที่ 250 คนกับคำสัญญา 10-14 ชิ้น
   ถ้าโค้ชตรวจไม่ทัน นักเรียนทั้งห้องจะหยุดวิ่งทั้งที่ส่งงานแล้ว
5. เปิดรุ่น แล้วค่อยทำ Phase 4 (แจ้งเตือน) ระหว่างรุ่นกำลังวิ่ง
